# 30 天，用 7 种编程语言做 7 个 AI 项目

> “神以前也是人，只不过他做了人做不到的事，所以他成了神。”

这是一个为期 30 天的开源编程挑战：使用 7 种不同的编程语言，完成 7 个与 AI
有关的项目。

项目从 TypeScript、Ruby、Python，一路写到 Haskell、Rust、Go 和 Zig。每种语言都不是
随机选择的，而是用来解决一个与它的生态、类型系统、并发模型或底层能力相匹配的问题。

这个挑战想回答一个问题：

> 当 AI 已经会写几乎所有编程语言时，我们还有必要学习编程语言吗？

也许语法本身没有以前那么重要了，但编程语言背后的范式、思想和取舍反而更加重要。
在 AI 辅助编程中，人仍然需要判断系统应该怎样拆分、边界应该放在哪里，以及哪一种工具
最适合当前问题。

## 为什么这样配对

### TypeScript × Tokenizer 可视化

TypeScript 拥有成熟的前端生态，适合构建交互式可视化工具。TokenLens 使用 React、
Web Worker 和本地 WASM，让用户直观看到一段文本如何被模型拆分为 Token，同时练习
类型化消息协议、异步状态管理、Unicode 与浏览器性能优化。

### Ruby × 大模型测试 DSL

Ruby 的元编程能力和富有表现力的语法，很适合设计接近自然语言的测试 DSL。项目将探索
如何为具有不确定性的 AI 系统提供清晰、可组合、可在 CI 中运行的评估规则。

### Python × 开源项目维护 Agent

Python 拥有完整的 AI 生态和丰富的工程工具链。这个 Agent 将从 GitHub Issue 出发，
理解代码库、规划修改、调用工具完成实现，并自动整理成可审查的 Pull Request。

### Haskell × Agent 工作流验证

Haskell 的强类型系统可以把一部分错误和安全约束提前到运行之前。项目将用代数数据类型、
状态机和类型级约束描述 Agent 工作流，检查非法状态迁移、缺失步骤和危险操作路径。

### Rust × 本地模型路由

Rust 在提供内存安全和并发安全的同时，拥有接近 C++ 的性能。项目将综合任务难度、
模型能力、延迟、成本与隐私要求，把请求路由到本地小模型或远程大模型。

### Go × 持久化 Agent Worker

Go 擅长构建可靠的并发后台服务。项目关注任务队列、检查点、重试、幂等和恢复机制，
确保一个经历数十次工具调用的长任务不会因为 Worker 崩溃而从头开始。

### Zig × 极简推理引擎

Zig 适合系统级编程，也允许开发者精确控制内存和数据布局。这个项目不会试图替代成熟的
推理框架，而是从权重加载、Tokenizer、Attention、前馈网络到采样，走通一次最小推理
过程，理解语言模型怎样生成下一个 Token。

## 学习主线

每个项目都会从三个维度展开：

1. **语言特性**：理解这门语言独有或最具代表性的表达方式；
2. **架构设计**：解释模块边界、数据流、运行时约束和关键取舍；
3. **AI 知识**：通过一个可以运行的项目理解 Token、评估、Agent、模型路由、
   持久化执行和推理等概念。

## 关于这个挑战

这个仓库不仅记录七个最终作品，也记录在 AI 辅助下学习陌生语言、做架构判断和完成工程
验证的过程。挑战能否在 30 天内全部完成尚未可知——毕竟光听到 Haskell 和 Zig，
脑袋就已经开始痛了。

争取最终每个项目至少留下五样东西：
1. 一个真实、明确的问题；
2. 一条可以运行的最小链路；
3. 自动化测试；
4. 一份关键架构取舍说明；
5. 一篇“AI 生成了什么、我判断了什么、哪里判断错了”的复盘。
